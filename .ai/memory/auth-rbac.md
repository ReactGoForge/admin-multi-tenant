# 认证与 RBAC 记忆

本文件记录后台认证、小程序认证、多租户和权限系统的长期安全边界。

## 后台认证

- 后台使用账号、密码、数字图片验证码和八小时 JWT；签发者是
  `admin-multi-tenant-service`，受众是 `admin-multi-tenant-admin`，算法固定 HS256，
  允许 30 秒时钟偏差。
- JWT 只保存员工 ID、工作空间、可选租户 ID、会话 ID 和标准时间字段，不保存角色或
  权限；角色、权限、员工状态和租户状态在请求时实时读取。
- 后台同一员工只保留最后一次登录会话。普通退出只清理浏览器 Token；本人修改密码会
  清空服务端会话，使普通、代管和保留的平台 Token 全部失效。
- 当前不实现 Refresh Token、Token 黑名单、Redis 会话、短信登录或服务端退出接口。
- 验证码默认启用并在 Redis 保存 120 秒，使用 `GETDEL` 一次性消费。
- 登录限流默认启用：十分钟内同账号失败五次或同 IP 失败二十次后锁定十五分钟；生产
  环境禁止关闭。Redis 安全能力异常时登录安全失败为 503。
- `TRUSTED_PROXIES` 只填写实际可信代理 IP 或 CIDR，禁止使用全网段。

## 平台代管

- 后台会话分为 `normal` 与 `managed`。平台角色分别配置平台权限和跨租户通用的租户
  代管权限。
- 代管 Token 保留真实平台员工身份，不冒充租户员工；进入和每次请求都实时检查平台
  员工、目标租户、平台角色及映射权限。
- 客户端不能指定可信租户范围，租户 ID 只来自认证上下文。
- 代管会话没有可访问页面时可以恢复原平台 Token；恢复失败时清理登录态。

## 小程序认证

- 小程序使用微信 `jscode2session` 和七天 JWT，受众是
  `admin-multi-tenant-miniapp`，不能与后台 Token 互用。
- 单一 AppID 下的 OpenID 是当前平台用户唯一微信身份；scene 是十进制租户 ID，同一
  用户通过 `tenant_users` 归属多个租户。
- 小程序 JWT 只保存用户 ID 与租户 ID，不保存手机号、头像、OpenID 或微信凭证。
- 平台用户、租户和租户用户关系状态在每次受保护请求中实时校验。
- 首次只有 scene、没有 Token 时等待用户主动登录；401 保留 scene 并自动重新登录，
  网络错误不清理原会话；跨租户登录成功后才替换原会话。
- 手机号和头像授权均可跳过。手机号只接受微信服务端用 `phoneCode` 返回的可信号码；
  微信配置缺失时后台仍可启动，但小程序登录返回服务不可用。
- `WECHAT_MINIAPP_CODE_ENV_VERSION` 只接受 `develop`、`trial`、`release`，分别对应
  本地、测试和生产小程序码。

## RBAC

- `/me` 返回当前工作空间的实时启用角色、权限和菜单；多角色权限取并集，平台超级管理
  员动态放行。
- 页面按工作空间和 `view` 权限控制，按钮按操作权限控制；无权限返回 403。
- 普通管理员只能创建、配置或分配自身实时权限的子集；超出授权边界的角色只读且不可
  分配。
- 正常会话且拥有员工编辑权限时，可以在员工页面编辑本人基础资料；本人仍不能为自己
  分配角色、后台重置密码、启停或删除，密码通过个人信息页面修改。
- `platform_super_admin`、`platform_admin` 和 `tenant_owner` 等内置角色的名称、状态
  和删除受保护。
- 平台超级管理员可以配置 `platform_admin` 和 `tenant_owner` 权限；普通租户身份只能
  查看企业管理员角色。
- 租户自定义角色和平台代管权限禁止分配 `tenant:menu:*`；企业管理员只有平台超级管理
  员可以手动授予该类权限。
- 平台基础设置和微信小程序配置使用查看与编辑分离的权限；普通角色需要显式授权。

## 租户边界

- 创建租户时在单个事务中创建租户、企业管理员角色、所有者员工、角色关联和默认权限
  快照，并回写 `owner_employee_id`。
- 企业管理员默认获得全部可分配租户节点，但排除 `tenant:menu:*`；平台新增可分配租户
  节点时自动补给全部企业管理员。
- 租户接口的所有查询和写入同时限制工作空间与认证上下文中的租户 ID。
- 企业管理员角色不能由普通租户身份编辑、停用、删除、移除或分配给其他员工。
- 租户停用后，已有后台和小程序会话在下一次认证时失效。

## 未来统一用户身份边界

- 当前没有 H5、短信登录、用户密码登录或独立身份表；以下规则只约束未来实现，不代表
  已经授权开发。
- `users.id` 继续作为唯一用户主体，业务数据只关联用户 ID；手机号与微信只是登录身份。
- 每个用户最多绑定一个手机号和当前小程序 AppID 下的一个微信号；手机号和 OpenID 都
  必须全局唯一归属一个用户。
- 已有手机号用户绑定微信时复用原用户 ID；身份冲突必须拒绝，不在登录流程中自动覆盖、
  换绑或合并。
- 未来身份表、唯一约束、数据迁移、短信、换绑、恢复和账号合并必须在真实需求出现时
  重新检查数据并单独批准。
