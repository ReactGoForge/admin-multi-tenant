# 品牌与媒体记忆

本文件记录平台品牌、租户品牌、图片库、头像和 MinIO 能力。处理图片上传、品牌图标、图库、头像或对象存储时读取；不得记录临时分析、猜测或未确认方案。

## 品牌设置

- 平台基础设置已支持平台名称和平台图标；平台品牌应用于平台侧栏、登录页和浏览器标题。
- 租户工作空间优先显示租户名称与租户图标，缺少租户图标时回退平台图标。
- 平台与租户基础设置只保存图片 ID：平台图标只能引用平台共享图片，租户图标可以引用当前租户图片或平台共享图片。
- 公开图片代理只允许读取当前正被平台或租户品牌引用的图片。

## 图片库

- 图片二进制保存到现有私有 MinIO Bucket，数据库只保存分类、所有者、真实 MIME、大小、对象键和上传员工等元数据。
- 接口不会返回对象键、访问密钥或 Secret，后台图片列表仅返回 15 分钟有效的 Presigned GET URL。
- 后端媒体模块已按 Handler → Media Service → Store/Storage 分层；Handler 不直接访问 Store 或对象存储，图片上传、删除、预签名、公开品牌图片读取和头像替换补偿语义由 Media Service 编排。
- 图片能力已抽取为公共 `ImageLibrary` 图库主体，独立图片库页面使用管理模式，`ImagePicker` 只维护触发器、选择弹窗和待确认值。
- 两种入口复用来源、分类、搜索、分页、上传、预览、重命名、改分类、删除和批量管理。
- 图库采用左侧同级单层分类树、右侧紧凑图片网格；管理模式默认不点击选图，仅在批量模式勾选。
- 组件默认单选并可通过 `multiple` 与可选 `maxCount` 开启受限多选。
- 平台可以按租户筛选并直接管理租户图片，租户只能管理自身图片，且只读浏览或选择平台“共享图片”系统分类内的图片。
- 图片列表每页固定 10 张并使用浏览器原生图片懒加载。
- 平台与租户 `/images` 已作为顶级“图片库”菜单按 `image:view` 权限控制导航和直达访问。

## 上传、删除与头像

- 服务端单次上传只接受真实可解码的 PNG、JPEG、WebP 单图，最大 5MB；前端选择器支持多文件选择并最多并发 3 个复用单文件接口。
- 不支持 SVG、GIF、裁剪、压缩、缩略图或重复文件合并。
- 被平台或租户品牌引用的图片禁止删除；删除分类后图片转入未分类。
- 员工头像复用私有 MinIO 和 `image_assets`，但从通用图片列表、编辑、品牌选择和删除操作中排除。
- Web 前端使用 `react-easy-crop@6.2.2` 将不超过 5MB 的 PNG、JPEG、WebP 原图裁剪为 512×512 WebP，并继续在客户端限制裁剪结果不超过 2MB；服务端统一重新验证真实格式、正方形和 5MB 上限，请求体上限为 6MB。
- 头像归属始终按真实员工身份确定，代管状态修改平台员工本人头像；替换时数据库事务同步切换员工引用和旧元数据，并尽力补偿对象清理。
- 小程序用户头像复用同一私有 MinIO，但不写入 `image_assets`；`users.avatar_url` 保存随机私有对象键，登录、`/me` 和后台用户列表只返回 8 小时临时签名地址，签名失败降级为空头像。
- 小程序头像在客户端通过 Taro 压缩为 512×512、质量 80，读取文件信息并确认不超过 5MB 后上传，压缩或读取失败不上传原文件；服务端限制真实 PNG、JPEG 或 WebP、正方形且最大 5MB，并按“写入新对象、锁定启用用户替换对象键、成功后尽力删除旧对象”处理，数据库失败时补偿删除新对象。

## MinIO

- MinIO 通过 `MINIO_*` 服务端环境变量配置，真实密钥不进入前端或数据库。
- 配置缺失、Bucket 初始化失败或对象存储异常不会阻止后台服务启动，只使图片相关接口返回 503。
- 租户小程序码复用同一私有 Bucket 按真实 JPEG 或 PNG 格式保存原图，但不写入 `image_assets`；缓存不可用时降级为直接调用微信并返回生成结果。
- `minio-go/v7` 是本功能唯一新增运行依赖。
